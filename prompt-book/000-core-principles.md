## 첫 화면: 이것만은 잊지 마세요

### ① 섣불리 답하게 하지 마라
빠른 답이 틀린 방향을 고착시킵니다.
→ "지금 바로 답하지 말고, 먼저 나에게 필요한 것을 물어봐. 내가 답하면서 같이 방향을 잡아가자."

**검증:** LLM 앵커링 효과 연구 — 초반 성급한 답변이 이후 전체 응답을 오염시킴

### ② 계획 중엔 실행하지 마라
(바이브코딩 원칙 → 모든 영역 적용)
→ "지금은 계획 단계야. 결과물 만들지 마. 충분히 대화하고 방향이 잡히면 그때 시작해."

### ③ 가이드와 답은 다르다
무엇을 해야 할지 순서를 알려달라는 것과 답을 내달라는 건 전혀 다른 요청
→ "해결책 말고, 내가 생각해야 할 순서를 먼저 알려줘."

### ④ AI도 틀리고, 나도 틀린다
→ 결과를 맹신하지 말고, 질문을 의심하라. 좋은 협업은 서로의 오류를 잡아주는 것.

### ⑤ AI보다 본업을 먼저 공부하라
→ AI가 막히면 AI를 공부하지 말고 본업 책을 펴라. 키워드와 인사이트 문장을 수집하라.

## 언어 선택 원칙 — 한국어 vs 영어 vs 혼용
*출처: 강사 현장 경험 + 다국어 LLM 성능 연구 (arXiv 2025)*

### 원칙: 영어가 항상 정답이 아니다

| 상황 | 권장 언어 | 근거 |
|------|-----------|------|
| 한국 문화·시장·법률·제도 관련 | **한국어** | 콘텐츠 언어와 프롬프트 언어를 일치시킬 때 최대 50% 정확도 향상 |
| 글로벌 학술·기술·비즈니스 | **영어** 또는 혼용 | 영어 학습 데이터 압도적으로 많음, factual accuracy 우수 |
| 창의적 발상, 감성 콘텐츠 | **혼용** | 언어 혼용이 추론 성능 향상 가능 (언어 전환 시 단일 언어 대비 성능 저하 관측) |
| 이미지·영상 생성 AI | **영어 (LLM이 작성)** | 주요 이미지 AI는 영어 데이터셋으로 집중 훈련됨 (Stable Diffusion: LAION 영어 서브셋) |

**검증:**
- "Better To Ask in English?" (arXiv:2504.20022) — 영어가 factual accuracy 우세
- "Quantifying Multilingual Performance" (arXiv:2404.11553) — 콘텐츠 언어 일치 시 50% 향상
- "The Impact of Language Mixing on Bilingual LLM Reasoning" (arXiv:2507.15849) — 혼용이 추론 향상 가능
- 기계 번역(파파고식) 프롬프트: 정확도 50% 미만 (실무 사례 기반, 공식 논문 없음)

### 이미지·영상 AI 프롬프트: 파파고 금지

이미지·영상 생성 AI(Gemini 이미지, Midjourney, Runway 등)는 일반 LLM과 다르게 **번역 능력이 약하다**. 영어 데이터로 집중 훈련되어 있어, 단순 번역툴(파파고) 결과를 그대로 쓰면 어색한 이미지가 나온다.

**올바른 방법:**
```
❌ 한국어 그대로 입력
❌ 파파고로 번역 후 붙여넣기
✅ LLM(Claude, ChatGPT)에게 이렇게 요청:
   "[원하는 이미지 내용]을 Gemini 이미지에 사용할
   영문 프롬프트로 만들어줘. 조명, 렌즈, 분위기 등
   이미지 AI 문법에 맞게 작성해줘."
```

**강사 팁**: 혼용 전략(한국어 지시 + 영어 전문 용어)은 LLM이 더 많은 학습 경로를 활성화하게 만들어 답변 품질을 높이는 경우가 있습니다. 단, 이미지·영상 AI에는 적용하지 마세요.

## 프롬프트 작성 전 3원칙
*출처: 검색의 즐거움 (책) → 강사 강의 적용*

### 원칙 1. 내가 무엇을 원하는지 안다
**메타 프롬프트:**
```
나는 지금 [A]와 [B]를 원하는데, 정확히 무엇을 어떻게 원하는지는 아직 구체적이지 않아.
내가 원하는 최종 결과물을 얻을 수 있도록 나에게 추가 질문을 해줘.
```

### 원칙 2. 필요한 키워드를 안다
- 도메인 전문 용어를 알수록 AI 결과가 달라진다
- 모를 때: 이 프롬프트 라이브러리에서 키워드를 찾아 쓰거나, 도메인 책에서 수집

### 원칙 3. 원하는 출력 형태를 안다
- ❌ "표로 줘", "리스트로 줘" → 너무 약함
- ✅ "16:9 슬라이드, 주요 포인트 톤다운 레드, 배경 흰색"처럼 구체적으로

## 핵심 원칙 (강사 + 논문 검증)

### 싱글턴 vs 멀티턴
**원칙: 할 수 있다면 싱글턴으로**

| | 멀티턴 | 싱글턴 |
|--|--------|--------|
| 성능 | 39% 저하 | 기준값 |
| 신뢰성 | 112% 악화 | 기준값 |

**검증:** Microsoft Research arXiv 2505.06120 (2025) — GPT-4.1, Claude 3.7, Gemini 2.5 포함 15개 LLM 전부 동일

```
싱글턴 프롬프트 기본 구조:
[역할] + [맥락/배경] + [제약조건] + [원하는 것] + [출력 형식]
모든 정보를 한 번에 담아서 질문
```

### Zero-shot vs Few-shot

| 상황 | 권장 |
|------|------|
| 브레인스토밍·아이디어 발산 | Zero-shot (예시 없이) |
| 정확한 형식 필요 | Few-shot (예시 제공) |

**검증:** Wharton School (2024) — AI 아이디어의 80%가 3개 카테고리에 집중, Few-shot이 창의성 제한

### 제약 조건 (가장 중요한 단 하나의 요소)
```
나는 [직급/역할]이고, 가용 예산은 [금액], 기간은 [기간]이야.
이 조건 안에서 알려줘.
```
**없으면:** 대리가 물어봐도 임원급 5년 프로젝트 설계안이 나온다

### 말로 하는 프롬프트
- 인지과학적으로 말하기 > 글쓰기 (자연스러운 발산)
- Jeremy Utley (Stanford d.school): "대화 형식이 명령형 텍스트보다 효과적"
- 실수도 괜찮다. AI는 맥락을 읽는다

## 프롬프트 프레임워크 비교

| 프레임워크 | 구성요소 | 적합한 상황 |
|-----------|---------|------------|
| PTCF (Google) | Persona·Task·Context·Format | 일반 업무 |
| GCES (Microsoft) | Goal·Context·Expectations·Source | Copilot 환경 |
| CO-STAR | Context·Objective·Style·Tone·Audience·Response | 고품질 콘텐츠 |
| RISEN | Role·Instructions·Steps·End Goal·Narrowing | 복잡한 다단계 |
| APE | Action·Purpose·Expectation | 빠른 작업 |
| RTF | Role·Task·Format | 입문용 |

**강사 팁:** 정답은 없다. 사용자에 따른 해답이 있다.
